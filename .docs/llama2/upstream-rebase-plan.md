# llama2 → upstream forward-port plan

Date: 2026-05-25. Branch: `feat/std-math-llama2` (merge-base `c1618a2`, 2026-05-19) vs `upstream/main` (`b134668`, 2026-05-25). 296 upstream commits, 36 ours.

Decision taken: **forward re-port onto upstream/main** (not merge/rebase). Scope: **Tier A first** (in progress); Tier C (incl. int8) is the eventual target, as separate later work. **Live status: §9. Workspace/how-to-resume: §10.**

---

## 1. TL;DR

A merge is dead on arrival. Upstream did two sweeping things since our merge-base:
1. **Replaced the entire `.0` language syntax** ("row syntax", prefix + indentation) and **deleted the old parser**. Every llama2 source file and fixture is now syntactically invalid.
2. **Rewrote the compiler backends** into shared primitives + a full native cross-platform target matrix (linux-x64, darwin-arm64, linux-arm64, win-x64, win-arm64).

Our llama2-enabling compiler features (std.math/libm, std.fs.mmap, `bytesAs*` reinterprets, **f32/f64 arithmetic itself**) are **absent upstream** and must be re-implemented on the new architecture. Our hand-ported macho64/elf_aarch64 backends are **superseded** by upstream's — we drop them and add features to upstream's backends instead.

Path: branch off `upstream/main`; re-implement compiler features; rewrite example + fixtures in row syntax; re-wire harness; re-validate.

## 5. New-syntax rewrite reference (for §6 P-EX)

Full mapping in research; essentials:
- `fun name(p: T) -> R raises {…}` → `fn name R p T !` + indented body. Return type **first**. `pub`/`export c` prefixes.
- `shape X {a: T,}` → `type X` / indented `a T`. Literal `X{a:1}` → `X . a 1` (**single line — multi-line unverified, RISK**).
- `let x: T = v` → `let x T v`; `let mut` → `mut x T v`; reassign `x = v` → `set x v`.
- Operators **prefix**, compound operands parenthesized: `a+b*c` → `+ a (* b c)`; `a<b && c` → `&& (< a b) c`.
- `return` → `ret`; `while c {…}`/`if c {…} else {…}` → indented, prefix cond. break/continue exist but **keep llama2 sentinel loops** for behavior parity.
- Calls drop parens/commas: `f(a,b)` → `f a b`; zero-arg keeps `()`. Cast `(x as T)` parenthesized as operand. `check`, `raise`, `&`/`&mut`, slices `a[i..j]`, `.has/.value`, generics `Span<f32>` unchanged in spelling.
- Indentation: 2 spaces/level, no braces/semicolons, one stmt/line.
- **Preserve all load-bearing local-binding patterns** (bind-before-record-literal, bind-sliced-span-before-index) — backend constraints persist.

## 8. Risks / open questions

1. **Multi-line record literals** unverified in row syntax; llama2 has large literals (Config 8 / RunState 15 / TransformerWeights 12 fields). If only single-line accepted, lines get very long or need refactor. **Verify early in P-EX.**
2. **Float lowering × 5 sites** is the schedule driver; macho64 (darwin arm64) is a separate path from aarch64_direct.
3. **mir_verify** is a new hard gate — every new IR kind needs a contract or builds are rejected.
4. **libm on ARM64-ELF/COFF**: aarch64_direct has no runtime-patch machinery — needs a new callback (only non-symmetric spot).
5. Upstream still moving fast (296 commits/wk) — re-port against a pinned `b134668`, rebase once.
6. Backend float behavior must match for token-for-token parity (FMA contraction etc. — see existing parity notes; int8 bit-exactness only on matched-musl targets).
